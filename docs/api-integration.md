# API 연동 기록

서버가 제공한 `FRONTEND_API.md`와 운영 릴리스 `5b63e39`의 OpenAPI를 기준으로 차량 앱을 연결했다. 운영 주소는 `https://35.216.33.209`이며 출발·주차·계정 발급용 팀 토큰은 차량에 전달하지 않는다.

## 연결과 역할

운행 연결에서 발급받은 accountId와 개인 accessToken을 입력한다. 토큰은 기본적으로 메모리에 유지한다. 사용자가 기기 계정 보관을 선택하면 Android Keystore 키로 AES-GCM 암호화해 기기 내부에 저장하며, 연결 해제 시 해당 저장 정보도 지운다. accountId는 화면에서 본인·소유자·보호자 동작을 구분하기 위한 인계 정보이며, 요청 권한의 최종 판단은 서버가 개인 토큰으로 수행한다. 토큰에서 계정 UUID를 추측하지 않는다.

운행 상세를 조회해 owner, occupants, receipts, phase를 갱신한다. 탑승자가 아닌 지정 보호자는 타임라인 권한 없이도 자신의 동의 화면을 열 수 있다. 본인은 PASSENGER, 지정 보호자는 아동의 GUARDIAN 경로로 제출한다. 필요한 영수증이 없으면 미응답으로 표시한다.

## 연결된 화면

| 상태·화면 | 구현 |
| --- | --- |
| DRIVING | 소유자의 성인·아동 초대 링크 발급, 아동 보호자는 탑승 성인 중 선택. 링크 만료 및 화면 비활성화 시 표시 종료 |
| PENDING 이후 | 본인·보호자의 추출·전사 동의, 위치·동승자 재생 선택 동의. 거절·철회 결과를 확인 화면에 안내 |
| UPLOAD | 소유자가 파일 선택기로 전방·후방 MP4를 각각 선택하고 전송. 위치 동의가 모두 있으면 출발지·도착지 등록 |
| READY | 소유자의 15초 추천 생성, 작업 ID 저장·조회 재개. 작업 FAILED·빈 추천 처리 |
| 추천 상세 | 선택 버전의 재생·제목·기존 구간 안 자르기·기존 순서의 전체 자막 수정. 새 작업 ID로 재생·QR·확정 |
| 타임라인 | 작성자 이름, 상태·장소 표시, 재생 가능한 표시를 자신의 앨범에 선택 |
| 저장 | 확정 선택을 요청 전에 저장. 응답 유실 후 같은 jobId·moment로 재시도. SAVING을 조회하고 SAVED 후 보관함 갱신 |
| 보관함 | 서버 clipUrl 우선 재생, 구형 주 보관본만 fallback 사용. 표시 클립에는 주 보관본 QR 숨김 |
| QR | 발급·만료·회수, 일회 다운로드 안내. 초대 URL·QR·토큰을 로그에 출력하지 않음 |
| 폐기 | 운행 ID와 전체 탑승자 영향 확인 후 삭제 요청. 해당 타임라인 갱신 |

원본은 작은 버퍼로 두 번 읽는다. 먼저 실제 바이트 수·소문자 SHA-256을 계산하고, 같은 파일을 고정 길이 스트리밍으로 전송한다. 8 GiB 초과·빈 파일·읽기 사이 길이 변경을 거절한다. 서버가 영상·오디오·해시를 최종 검증하며 실패한 side만 다시 전송할 수 있다. 파일 전체를 메모리나 임시 복제본으로 만들지 않는다.

MP4는 Bearer 요청으로 임시 파일에 받아 재생하며 닫을 때 삭제한다. 서버가 반환한 재생 URL도 같은 HTTPS 원점의 API 경로만 허용하고 리다이렉트를 따르지 않는다. 재생 중 5초마다 타임라인·보관함의 접근 상태를 확인해 공유 철회·삭제가 확인되거나 접근 확인이 실패하면 재생을 닫는다.

## 검증

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

차량 단위 테스트 24개는 운행 ID 전체 보존, 개인 토큰의 외부 원점 전달 차단, 본인·보호자 역할과 전원 위치 동의 조건, 실제 업로드 요청의 원본 바이트·길이·해시, HTTP 실패, 편집 경계와 자막 배열을 검증한다. 네트워크 계약 테스트는 가짜 HTTPS 연결을 사용한다. 운영 계정을 발급하거나 운영 데이터를 생성·삭제하지 않았다.

운영 서버의 공개 상태 API 및 OpenAPI 연결은 확인했다. 실제 개인 계정·운행·원본을 사용하는 전체 흐름은 별도 검증이 필요하다. accountId와 토큰은 운영 인계 경로로 받아 화면에 입력하며 저장소나 로그에 넣지 않는다.

자동 카메라 원본 공급, 차량 출발·주차 신호, 위치 이벤트 자동 수집, Instagram 실기기 인계는 별도 검증 대상이다. 휴대폰 초대 수락·동의·업로드·편집·보관 화면은 passenger-web/index.html에 구현했으며 정적 HTTPS 호스팅과 초대 URL 연결 설정이 필요하다. 기존 example.html은 합성 데이터 예시다.


## 프론트 추가 완성 범위

- 휴대폰 컴패니언의 개인 계정 연결·초대 수락·이름 변경·순간 표시·동의·보관함, 소유자 업로드·편집·저장·QR 화면을 구현했다.
- 브라우저는 기본 메모리 세션과 사용자가 선택하는 암호화 계정 보관을 지원한다. 초대·순간·저장의 응답 유실 재시도 정보를 유지하며 평문 토큰은 브라우저 저장소에 넣지 않는다.
- 차량 앱에 이름 변경, 장소 이벤트 편집, 서버 출력 옵션 선택, 추천 근거 표시, 요청 취소, 외부 동의·운행 상태 갱신을 추가했다.
- 디버그 앱은 홈에서 주행 시연을 시작하고 기록 화면에서 주차 시연으로 돌아올 수 있어 adb 조작 없이 시연한다. 실제 차량 주행 제한 중에는 이 버튼을 제공하지 않는다.
- 로컬 시연 타임라인에서 완성 여부와 무관하게 경로 영역 배치를 통일했다.
- 서버 상태 확인 시 카메라·차량·내비·위치·스토리 연동 가능 여부도 표시한다. 사용 불가 기능을 연결 완료로 표시하지 않는다.
- 휴대폰 테스트 명령은 `npm ci --prefix passenger-web && npm test --prefix passenger-web`이다. API·해시·암호화·DOM 화면 흐름 테스트 16개를 포함한다. 브라우저 시각 검증은 컴퓨터 사용 권한이 없어 수행하지 못했다.

서버가 제공하지 않는 템플릿·BGM 렌더링, 결제·구독, MY HYUNDAI 동기화 등을 동작하는 기능처럼 표시하지 않는다. 실제 SDK·원본 공급·호스팅·CORS·Meta 앱 설정을 확보해야 운영 기기에서 전체 흐름을 확인할 수 있다.

Pleos 에뮬레이터에서 테스트 전용 저장소를 사용한 Android Keystore 암호화·복원·교체·삭제 테스트 1개도 통과했다. 실제 사용자 계정 저장소는 테스트하지 않는다.
